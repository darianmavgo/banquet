Recommendations

What Banquet Bar Should Adopt from Omnibox

⌨️
High Priority

History Navigation with ↑/↓

Chrome lets users browse history directly in the omnibox by pressing ↑/↓. Banquet Bar should maintain a session history stack of evaluated URLs and allow ↑/↓ in the bar to cycle through them — exactly like shell history.

Implement as a []string history slice on the model. ↑ in textinput = recall previous URL. On Enter evaluation, push to stack if different from top. Clear "future" stack on new navigation.
💡
High Priority

Inline Autocomplete & Schema Suggestions

Chrome shows top completions inline as you type. Banquet Bar has a unique advantage: it knows the open database's schema and can offer table names and column names as Tab-completions when the user types a partial path.

On each keystroke, resolve dataset path, run PRAGMA table_list or PRAGMA table_info, and offer matching names as a Tab-to-complete inline ghost suggestion at the end of the bar.
📋
High Priority

Dropdown Suggestion Panel

Chrome renders up to 8 ranked results below the omnibox. Banquet Bar should render a dropdown panel showing recently visited URLs, table names, and nearby databases from the active collection context.

Use bubbles/list as an overlay below the bar while the user types. Populate with: recent history, matching tables from open db, known .db/.sqlite files in the current directory.
⬅️
High Priority

Back / Forward Navigation

Chrome's Alt+← and Alt+→ move through the browsing session. Banquet Bar should support Alt+← / Alt+→ (or Ctrl+[ and Ctrl+] in terminal) to traverse the history stack without re-typing.

Maintain a historyIdx int pointer alongside the history slice. Alt+Left = decrement; Alt+Right = increment. Load the URL at the new index into the bar and re-execute it against the viewport.
🔍
Medium Priority

Fuzzy Fallback / "Did you mean?"

When input is unrecognized, Chrome falls back to a search. Banquet Bar should use fuzzy matching against known table names and file paths to suggest the closest match when a query fails, rather than a bare error.

On executeCommand error, run a Levenshtein or prefix match against known tables in the open database. Display a footer hint like: "Did you mean: 'steps'?" with a keybinding to accept.
⭐
Medium Priority

Saved Queries / Bookmarks

Chrome bookmarks let users one-click to any URL. Banquet Bar should support pinning frequently visited Banquet URLs (e.g. file:///prod.sqlite/users/-created_at) and recalling them from a shortcut.

Persist a ~/.config/banquet/bookmarks.json list. Press Ctrl+D to bookmark the current URL; show bookmarks at the top of the dropdown suggestion panel.
🔒
Medium Priority

Path Validity Indicator

Chrome shows a padlock or warning glyph based on HTTPS trust level. Banquet Bar should display a small prefix glyph indicating whether the current path resolves to a valid file (✓), a collection (📁), or is invalid (⚠) — before pressing Enter.

On each keystroke, run a lightweight os.Stat check on the parsed dataset path. Show a colored glyph at the leftmost position in the bar — no query execution required.
🤖
Future / Aspirational

Natural Language SQL Generation

Chrome 120+ added AI Overviews and Lens. Banquet Bar has a unique opportunity: accept natural language like "show me the 10 most recent errors" and translate it to a Banquet URL like /steps/-idx[0:10]?where=status=2 via an LLM.

Detect non-URL input (no file://, no extension heuristic match). Send to a local Gemini / Ollama endpoint with the schema as context. Insert the returned Banquet URL into the bar for user confirmation before executing.
Don't Lose These

Banquet Bar Advantages to Preserve

🎨

Color-Coded Path Segmentation

Banquet Bar highlights each URL segment in a distinct color (database → purple, table → cyan, clause → green). Chrome only dims the path. This should be kept and extended to all clause types.

🗄️

Schema-Aware Path Grammar

Banquet knows extension heuristics (.sqlite, .db), slice notation ([0:20]), sort modifiers (-col), and equality filters (col!=val). Chrome has no concept of data schemas.

⚡

Terminal-Native UX

No mouse required. Keyboard-first design, composable commands (cd, open, ..), and clipboard-via-shell mean Banquet Bar fits perfectly into developer and data analyst workflows without any GUI overhead.
